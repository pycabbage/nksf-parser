# アーキテクチャデシジョンレコード（ADR）

このディレクトリは、nksf-parserプロジェクトの重要な設計決定を**アーキテクチャデシジョンレコード（Architecture Decision Record: ADR）**として記録する。

ADRとは、ソフトウェアのアーキテクチャに関わる一度きりの決定を、その背景（コンテキスト）・内容（決定）・根拠（理由）・結果（影響）とともに短い文書として残すプラクティスである。「なぜこの実装になっているのか」を後から参加した開発者や未来の自分がコードを読まずに理解できるようにすることが目的である。

## 新しいADRの追加方法

1. **次の番号を採番する**: 既存の最大番号 + 1 をファイル名の接頭辞とする（例: `0007-<short-title>.md`）。番号の再利用や空き番への挿入は行わない。
2. **標準フォーマットに従う**: 既存のADRと同じ見出し構成（日付 / ステータス / コンテキスト / 決定 / 理由 / 影響・結果 / 代替案）で記述する。
3. **イミュータブルに保つ**: 一度承認済み（Accepted）となったADRの本文は書き換えない。判断が変わった場合は新しいADRを発行し、旧ADRのステータスを「廃止（Superseded by 00XX）」に更新して新ADRへリンクする。
4. **索引を更新する**: 上記の一覧表に新しい行を追加する。
5. **1つのADR = 1つの決定**: 複数の独立した決定を1つのADRに詰め込まない。関連するが別の決定は別ADRとして発行し、相互にリンクする。
