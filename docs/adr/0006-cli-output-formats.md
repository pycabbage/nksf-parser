# 0006: CLI出力形式とオプション設計

## 日付

2026-01（単一JSON出力として開始し、複数ファイル対応・JSONL対応を経て同年に確定）

## ステータス

承認済み（Accepted）

## コンテキスト

`nksf-parser-cli`は、パースライブラリ（[ADR 0001](0001-lib-cli-workspace-separation.md)）の解析結果を利用者が扱いやすい形で受け取るためのフロントエンドである。当初は「1ファイルをpretty JSONでstdoutへ出力する」だけの最小構成だったが、実用には以下のニーズがあった。

- **バッチ処理**: ライブラリ全体（数百ファイル）を一括で変換したい
- **出力先の制御**: stdoutではなくファイルや特定ディレクトリへ書き出したい
- **下流ツール連携**: 行指向フォーマット（JSONL）でgrep / jq / ストリーム処理に渡したい
- **安全性**: 既存ファイルをうっかり上書きしないこと

初期実装では pretty/compact を切り替える `-c, --compact` フラグを提供していたが、JSONL導入時にその役割が重複・混乱を生じた。

## 決定

CLIのオプションと出力仕様を次のように定める。

### オプション

| オプション | 説明 |
|-----------|------|
| `<INPUT>...` | 入力 .nksf ファイル（複数指定可） |
| `-o, --output <FILE>` | 出力ファイル名 |
| `-d, --dir <DIRECTORY>` | 出力ディレクトリ |
| `--jsonl` | JSON Lines形式で出力 |
| `--overwrite` | 既存ファイルの上書きを許可 |

### 出力仕様

**単一ファイル**

- デフォルト: pretty-print JSONをstdoutへ出力
- `--jsonl`: 1行のコンパクトJSONをstdoutへ出力
- `-o`指定時: 指定ファイルへ書き出し（形式は上記に準ずる）

**複数ファイル**

- `-o`指定時: 全入力を1つのJSONLファイルへ結合（各行が1プリセット）
- `-d`のみ（`--jsonl`なし）: ディレクトリ配下にプリセットごとの個別`.json`ファイル
- `-d` + `--jsonl`: 自動命名で1つのJSONLファイルへ結合。命名規則は **`{先頭ファイルのstem}_{ファイル数}files.jsonl`**（例: `preset1.nksf preset2.nksf preset3.nksf` → `preset1_3files.jsonl`）

**共通規則**

- JSONLは常にコンパクト（1行1オブジェクト）。pretty JSONはデフォルトのみ
- 既存出力ファイルがある場合、`--overwrite`なしではエラー終了する
- エラーと進行状況はstderrへ出力し、正常なJSONはstdoutを汚染しない
- エラー終了時の終了コードは1

### `--compact`の削除

`-c, --compact` オプションは削除する。コンパクト出力が必要な場面はすべてJSONLに集約されるためである。これは破壊的変更として受け入れる。

## 理由

- **形式フラグとモードフラグの分離問題**: `--compact`は「整形の有無」という見た目の問題だったが、実需要は「1ファイルならpretty、行指向処理ならcompact」という使い分けに集約される。JSONLという用途ベースのフラグに一本化することで、オプション空間が整理された。
- **JSONLの採用理由**: 大量プリセットの結合・ストリーミング・行単位フィルタリングに適する。jq等の標準ツールとの相性も良い。
- **自動命名規則**: 結合元が分かる名前（先頭ファイル名）と件数を持たせることで、後から内容を推測できるようにした。
- **上書き保護のデフォルト化**: バッチ実行時の事故を防ぐため、明示的な`--overwrite`を要求する。
- **stdout/stderrの分離**: パイプでの利用（`nksf-parser-cli x.nksf | jq ...`）を妨げない。

## 影響 / 結果

- 単一ファイル→複数ファイル→JSONLと段階的に拡張しても、デフォルト動作（単一ファイルのpretty JSON to stdout）は不変であり、既存のスクリプトは基本的に動作し続ける。
- `--compact`を使っていたスクリプトは`--jsonl`への移行が必要になる（破壊的変更）。
- 複数ファイル + `-o`指定時は常にJSONL結合となる仕様のため、「pretty JSONを1ファイルに連結する」ことはできない。必要であれば個別出力後に利用者側で処理する。
- エラーメッセージは`Error:` / `Hint:`の書式でヒント（例: `Use --overwrite to overwrite existing files`）を伴い、原因特定と対処が容易になった。
- CLI固有のロジック（出力先解決、命名、上書き判定）はすべてcliクレートに閉じ込められており、libのAPIには影響しない（[ADR 0001](0001-lib-cli-workspace-separation.md)）。

## 代替案

- **`--compact`の維持（JSONLと併存）**: 「JSONL=コンパクト」という規約が二重管理になり、`--compact`単体と`--jsonl`の組み合わせの意味論が曖昧になるため不採用。
- **`--format json|jsonl` の選択式**: 将来の形式追加（YAML等）には柔軟だが、現状の2形式では過剰設計であり、フラグの方が打鍵数も少ないため不採用。
- **既存ファイルへの追記モード / 対話的上書き確認**: バッチ用途では対話確認が障害になるため不採用。追記は結果の重複など事故のもとになりやすいため不採用。
