# 0003: 全バイト解析ポリシー（未知データの破棄禁止）

## 日付

2026-01（初期開発時に決定、同月に「unknown_chunks廃止」として確定）

## ステータス

承認済み（Accepted）

## コンテキスト

本プロジェクトの要件として、.nksfファイルの**完全なバイト解析**が掲げられている。

- ファイル内の全バイトを解析すること
- 1バイトも見逃さず、「不明なデータ」として捨てることを許可しない
- 解析できないデータがある場合はエラーを返す（無視しない）

一方、初期設計では `NksfFile` 構造体に `unknown_chunks: Vec<UnknownChunk>` というフィールドを設け、未知のチャンクを生バイトのまま保持する案も検討されていた。当時はNISI/NICA以外のチャンク（PLID/PCHK）の構造が未解明であり、「解明できていない部分をとりあえず保持する」ための場だった。

その後の調査で、.nksfファイルは **NISI / NICA / PLID / PCHK の4チャンクのみ**で構成され、全4チャンクが完全に解析可能であることが判明した。Massive X Factory Libraryの720プリセットすべてでこの構成が確認されている。

## 決定

1. パーサーは**入力の全バイトを消費する**。解析後に未読バイトが残っていた場合は `ParseError::IncompleteParse` を返す。
2. 未知のチャンクIDを検出した場合は黙ってスキップ・保存せず、**ハードエラー**（`ParseError::UnknownChunk`）を返す。
3. `NksfFile` から `unknown_chunks` フィールドを削除し、`UnknownChunk` 型も廃止する。`NksfFile`は`metadata` / `parameters` / `plugin_id` / `plugin_chunk`の4フィールドのみを持つ。
4. NISI/NICA/PLID/PCHKのいずれかが欠落している場合も `ParseError::InvalidNiks` で失敗する（必須チャンク検証）。

つまりパーサーの成功は「ファイルの全内容を構造化して保持した」ことと同値である。

## 理由

- **要件との整合**: 「不明なデータとして捨てることを許可しない」は、unknown_chunksへの退避によっても満たされない。生バイトのまま保持されたデータは利用者にとって構造化されていない未知領域であり、実質的に欠損と同じである。
- **全チャンク解析可能の裏付け**: 全720プリセットでの検証により、「解析できないチャンク」は現時点で存在しないことが確認された。unknown_chunksは不要な逃し道になるだけだった。
- **fail-fast**: 形式変更や破損を早期に検出できる。黙読み（黙って読み飛ばす）は後段で不可解なデータ不整合として表面化するより、解析時点でのエラーの方が原因究明が容易である。
- **型による保証**: `NksfFile`の4フィールドがすべて必須であることを型で表現でき、利用者側のOption分岐が不要になる。

## 影響 / 結果

- パース成功＝全データ構造化済み、という強い契約がライブラリAPIで保証されるようになった。
- unknown_chunks関連のコード・テスト・エクスポートはすべて削除され、コードベースが簡素化された。
- **将来のNI形式のバージョンアップで新しいチャンク種別やフィールドが追加された場合、パーサーはそれを黙って通さずエラーで失敗する**。これは意図的な挙動であり、新しい形式へ対応するにはパーサー自体の更新が必要である。互換性のための緩和策（警告、オプトインの無視など）は導入しない。
- 720プリセットのfixtureテスト（[ADR 0005](0005-test-architecture.md)）により、このポリシーが実際の全プリセットで成立することが継続的に検証されている。

## 代替案

- **unknown_chunksバッグ方式**: 未知チャンクを生バイト＋IDで保持する案。「何か取りこぼしがあるかもしれない」という不安を型に持ち込み続けることになり、全4チャンク解析可能という調査結果と矛盾するため不採用。
- **未知チャンクを警告付きでスキップ**: 将来の形式変更には寛容になるが、「全バイト解析」の要件に反し、静かなデータ欠損を招くため不採用。
- **未知フィールドの部分的な保持（例: `#[serde(other)]`的扱い）**: チャンク単位ではなくフィールド単位の緩和になるが、どのレベルまで許すかの基準が曖昧になり、契約が弱まるため不採用。
