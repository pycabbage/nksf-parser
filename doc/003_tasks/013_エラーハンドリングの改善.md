# 013: エラーハンドリングの改善

## 概要

エラーメッセージの改善と追加のエラーケース対応を実装する。

## 完了条件

- [ ] 全てのエラーケースで適切なエラーメッセージが表示される
- [ ] エラー発生時のコンテキスト情報（ファイル位置、チャンクIDなど）が含まれる
- [ ] CLIツールでユーザーフレンドリーなエラーメッセージが表示される
- [ ] エラーケースのテストが追加されている
- [ ] `cargo test -p nksf-parser` が成功すること

## 実装内容

### エラーコンテキストの追加

`error.rs` にコンテキスト情報を含むエラーバリアントを追加:

```rust
#[derive(Error, Debug)]
pub enum ParseError {
    // ... 既存のエラー ...

    #[error("Error reading chunk '{0}' at offset {1}: {2}")]
    ChunkReadError(String, u64, String),

    #[error("Invalid chunk size for '{0}': expected at least {1} bytes, got {2}")]
    InvalidChunkSize(String, usize, usize),
}
```

### エラーラッピング

各パーサーでエラーをラップしてコンテキストを追加:

```rust
// 例: nisi_parser.rs
pub fn parse_nisi_chunk(data: &[u8]) -> Result<NisiMetadata> {
    // ...
    let metadata: NisiMetadata = rmp_serde::from_slice(&data[4..])
        .map_err(|e| ParseError::ChunkReadError(
            "NISI".to_string(),
            4,
            e.to_string()
        ))?;
    // ...
}
```

### CLIエラーメッセージの改善

`cli/src/main.rs` でエラーの種類に応じた分かりやすいメッセージを表示:

```rust
let result = match nksf_parser::parse_nksf(&args.input) {
    Ok(nksf) => nksf,
    Err(e) => {
        eprintln!("Error: Failed to parse '{}'", args.input.display());
        eprintln!("Reason: {}", e);

        // エラーの種類に応じた追加情報
        match e {
            ParseError::IoError(_) => {
                eprintln!("Hint: Check if the file exists and you have read permission.");
            }
            ParseError::InvalidRiff => {
                eprintln!("Hint: The file is not a valid RIFF file.");
            }
            // ... 他のエラーケース ...
            _ => {}
        }

        process::exit(1);
    }
};
```

## テストケース

以下のエラーケースに対するテストを追加:

- 存在しないファイルを開こうとした場合
- 不正なRIFFフォーマットのファイル
- 不正なNIKSフォーマットのファイル
- 必須チャンク（NISI、NICA）が欠けている場合
- 不正なMessagePackデータ
- サポートされていないバージョン

## 注意点

- エラーメッセージは英語で記述
- ユーザーが問題を解決できるヒントを提供
- 開発者向けのデバッグ情報とユーザー向けのメッセージを区別
- エラーテストは `tests/` ディレクトリに配置
