# タスク018: テストライブラリの導入

## 概要

テストの表現力、実行速度、保守性を向上させるため、Rustエコシステムの標準的なテストライブラリを導入する。

## 目的

- **必須級**: テストの基本機能を強化（パラメータ化、スナップショット、アサーション改善）
- **強く推奨**: テストの品質を向上（プロパティベーステスト、パフォーマンステスト）

## タスク詳細

### 必須級ライブラリ (4つ)

#### 1. rstest
- **用途**: フィクスチャとパラメータ化テスト
- **導入理由**:
  - 720プリセットのテストで`#[case]`が有効
  - vitestの`test.for()`に相当する機能
  - フィクスチャでテストコードのDRYを実現
- **例**:
```rust
#[rstest]
#[case(1, 1, 2)]
#[case(1, 2, 3)]
#[case::special_case(0, 0, 0)]
fn test_add(#[case] a: i32, #[case] b: i32, #[case] expected: i32) {
    assert_eq!(add(a, b), expected);
}
```

#### 2. cargo-nextest
- **用途**: 高速テストランナー
- **導入理由**:
  - 標準テストランナーより高速
  - 並列実行の改善
  - リトライ機能
- **インストール**: `cargo install cargo-nextest`

#### 3. insta
- **用途**: スナップショットテスト
- **導入理由**:
  - 期待値データの管理を簡素化（phf_mapベースから移行）
  - スナップショット差分の視覚化
  - `cargo insta review`で変更を対話的に承認
  - インラインスナップショット対応
- **例**:
```rust
#[test]
fn test_parse_metadata() {
    let nksf = parse_nksf("fixture/Abandoned.nksf").unwrap();
    insta::assert_yaml_snapshot!(nksf.metadata);
}

#[test]
fn test_parse_full_preset() {
    let nksf = parse_nksf("fixture/Abandoned.nksf").unwrap();
    // 全データをスナップショット化
    insta::assert_yaml_snapshot!(nksf);
}
```

#### 4. pretty_assertions
- **用途**: アサーション強化（diff表示）
- **導入理由**:
  - テスト失敗時の可読性向上
  - カラフルなdiff表示
  - `assert_eq!`のドロップイン置き換え
  - dev-dependencyのみでビルド時間に影響なし

### 強く推奨ライブラリ (2つ)

#### 5. proptest
- **用途**: プロパティベーステスト
- **導入理由**:
  - パーサーの頑健性確認
  - エッジケース自動発見
  - 入力データの自動生成 + shrinking
- **例**:
```rust
proptest! {
    #[test]
    fn test_parser_never_panics(data: Vec<u8>) {
        // パーサーは不正な入力でもパニックしない
        let _ = parse_nksf_from_bytes(&data);
    }
}
```

#### 6. criterion
- **用途**: ベンチマーク（統計的に正確）
- **導入理由**:
  - 現在の`#[ignore]`パフォーマンステストを置き換え
  - パフォーマンス劣化を検出
  - 統計分析機能
- **例**:
```rust
fn criterion_benchmark(c: &mut Criterion) {
    let data = std::fs::read("fixture/Abandoned.nksf").unwrap();
    c.bench_function("parse_abandoned", |b| {
        b.iter(|| parse_nksf_from_bytes(black_box(&data)))
    });
}
```

## 実装手順

### ステップ1: 依存関係の追加

**IMPORTANT**: Cargo.tomlを直接編集せず、cargo addコマンドを使用すること。

```bash
# libディレクトリに移動
cd lib

# dev-dependenciesを追加（最新版が自動的にインストールされる）
cargo add --dev rstest
cargo add --dev insta --features yaml
cargo add --dev pretty_assertions
cargo add --dev proptest
cargo add --dev criterion --features html_reports
```

**手動設定の追加**:
以下の設定を手動で`lib/Cargo.toml`に追加する必要があります（cargo addでは設定不可）：

```toml
# Criterionベンチマーク設定
[[bench]]
name = "parser_bench"
harness = false

# insta/similarのパフォーマンス最適化（公式推奨）
# 大規模スナップショット（720プリセット）での高速化
[profile.dev.package]
insta.opt-level = 3
similar.opt-level = 3
```

### ステップ2: CLIツールのインストール

```bash
# cargo-nextest: 高速テストランナー
cargo install cargo-nextest

# cargo-insta: スナップショット管理ツール（公式推奨）
# Unix/Linux/macOS
curl -LsSf https://insta.rs/install.sh | sh

# Windows (PowerShell)
# powershell -c "irm https://insta.rs/install.ps1 | iex"
```

### ステップ3: 既存テストの移行（段階的）

**優先度順**:
1. **pretty_assertions**: 既存の`assert_eq!`をそのまま使用可能（use文追加のみ）
2. **rstest**: fixture_test.rsのパラメータ化テストに適用
3. **insta**: 既存のphf_mapベース期待値データをスナップショットに移行
   - massive_x_factory_library_tests/*_expected_data.rs → .snapファイルに置き換え
   - 720個のプリセット全てにinstaを適用
4. **proptest**: 新規テスト追加（パーサー頑健性）
5. **criterion**: benches/parser_bench.rs作成

### ステップ4: ドキュメント更新

- `CLAUDE.md`にテストコマンド追加
  - `cargo nextest run`
  - `cargo bench`
  - `cargo insta test`

### パフォーマンステスト
- 現在の`integration.rs`内の`#[ignore]`テストをcriterionに移行
- `benches/parser_bench.rs`に移動

### スナップショットテスト

#### instaへの移行
- 既存のphf_mapベース期待値データ（*_expected_data.rs、約400MB）をinstaスナップショットに置き換える
- スナップショットファイル（.snap）は`lib/tests/snapshots/`ディレクトリに保存される
- `cargo insta review`で変更を対話的に確認・承認できる
- 期待値の管理が容易になり、テストコードがシンプルになる

#### 移行の流れ
1. rstesetでパラメータ化テストを実装
2. instaでスナップショットを生成（`cargo insta test`）
3. スナップショットを確認・承認（`cargo insta review`）
4. 既存の*_expected_data.rsファイルを削除
